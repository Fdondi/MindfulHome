# CRAP metric (Change Risk Anti-Patterns)

CRAP combines cyclomatic complexity and test coverage to highlight methods that are risky to change:

```text
CRAP(m) = CC(m)^2 * (1 - coverage(m))^3 + CC(m)
```

This project computes it with:

1. **detekt** `CyclomaticComplexMethod` — source-level McCabe complexity (`CC`)
2. **Kover** — JaCoCo-compatible XML method coverage from local unit tests
3. **`scripts/crap/compute_crap.py`** — joins the two reports and ranks methods

Instrumented (on-device) tests are **not** included; Kover only instruments JVM/host unit tests.

`crapCheck` ignores unit-test assertion failures so a full coverage XML is still produced. Fix failing unit tests separately with `gradlew testDebugUnitTest`.

## Run

```bat
gradlew crapCheck
```

This runs unit tests with coverage, dumps per-method complexity via detekt, then writes:

- console: top 50 CRAP scores
- `results/crap/crap-report.md`

Optional hard gate:

```bat
gradlew crapCheck -PcrapMax=8.0
```

Exit code `2` means at least one method exceeded the threshold.

## Inputs / outputs

| Artifact | Path |
| --- | --- |
| Kover XML | `app/build/reports/kover/reportDebug.xml` |
| detekt XML (CRAP dump) | `app/build/reports/detekt/detektCrap.xml` |
| Markdown report | `results/crap/crap-report.md` |

## Interpreting scores

| Score | Typical meaning |
| --- | --- |
| near `CC` | well covered relative to complexity |
| much higher than `CC` | complex **and** poorly covered |
| classic gate | `8.0` (same default as `crap-java` / `crap4java`) |

Unmatched methods (detekt found them, Kover did not) are treated as **0% coverage**. That is intentional: missing coverage attribution should not look safer than it is.

Kotlin method names in Kover XML are often mangled (`foo-N6fFfp4`); `scripts/crap/compute_crap.py` strips the `-…` suffix when joining to detekt findings.

## Proposed exclusions

None at present — the `crapMax=42` gate passes without don’t-test carve-outs. If a future method is pure Android lifecycle / WindowManager glue with no remaining decision branches, propose it here for review before skipping coverage.

## Notes

- Regular `detekt` / `check` are not forced to fail the build by this setup; `detektCrap` is a separate metrics dump with `allowedComplexity: 0`.
- Compose/generated bytecode names can reduce match quality; the report’s `Matched` column shows join success.
